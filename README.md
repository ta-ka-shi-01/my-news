# My News v0.3.1

ゲーム業界・成人向け同人ゲーム・野球の個人向けニュース一覧です。Python標準ライブラリだけで収集・選別・話題整理を行い、有料AI APIは使いません。

## v0.3.1の変更
- 採用の関連性スコアと、表示順位・注目判定の重要度を分離。
- ゲームのグッズ・単純な発売記念日・キャンペーンを減点。周年に伴う実際の新作発表は保護。「新作発表はなし」も重大発表と区別します。
- 成人向け同人は規約・審査・決済、市場、制作に役立つAI、販売実績を優先。単発宣伝やキャンペーンは下げます。
- 野球はDeNA、NPB、MLB、高校野球の関心度を加点。DeNAを先頭固定せず、重大ニュースが上回れる方式です。
- 通常の試合結果、地方大会の決勝・組み合わせだけでは「注目」にしません。全国的な重大ニュースは残します。
- 同じ出来事の複数記事は代表記事と関連リンクに整理。独自取材・インタビュー・追加情報・重要な続報は残します。
- 各セクション5件と個別タブは、収集時に決めた同じ優先順を使用します。CSSと基本レイアウトは変更していません。

## 実行
1. `python collect.py` で収集（ネット接続が必要）。
2. `python -m http.server 8000` を実行し、ブラウザで `http://localhost:8000` を開く。
3. `python -m unittest discover -s tests` で収集・選別・順位・話題整理のテスト。
4. `node tests/test_ui.cjs` で表示処理テスト。追加パッケージ不要。
5. `python compare_ranking.py --output ranking-comparison.json` でv0.3とのサンプル比較。

保存記事も再評価する場合：`python compare_ranking.py --snapshot news.json --output ranking-comparison.json`。この比較は収集やnews.jsonの書き換えをしません。tests/baseline_v03内の納品済みv0.3を同じ入力で実行します。通常収集では比較用コードを使用しません。

## 設定と表示順位
`scoring.json` の従来のcontext・rules・thresholdは採用判定に使います。同じルールの加点・減点は1記事に1回です。重要な決算・規約等には採用保護があります。

新しい `ranking` 設定は表示用です。

| 設定 | 用途 |
| --- | --- |
| signals | 新作、企業動向、地方大会、編成等の手がかり |
| importance | ニュースの重要度。カテゴリとの関連性やDeNAへの関心とは別に評価 |
| notable_min | 「注目」の最低重要度。ゲーム・成人向け同人7、野球8 |
| interest | 野球の関心加点：DeNA7、NPB4、MLB2、高校野球0 |
| importance_weight | 重要度の重み：2 |
| freshness_max / half_life_hours | 新鮮さの加点：最大12、半減までゲーム・野球18時間、成人向け同人48時間 |
| age_penalty_hours / age_penalty_max | 古さの減点：48時間に1点、最大14点 |
| same_topic_penalty | 同じ話題が続く場合の減点：12点 |
| regional_top5_limit | 地方高校野球は原則上位5件に1件。採用済みの他の有用記事がある場合に適用 |
| diversity_min_importance | 多様性のために繰り上げる記事の最低重要度：3。競技外の話題や単なる販促を無理に上げません |
| keep_followups | 独自取材・追加情報等をまとめずに残す手がかり |
| story_window_hours / story_similarity | 同一話題と判定する時間幅と、見出しの類似度の下限 |
| material_terms | 対応機種・決済ブランド等の重要な違いを残すための語 |

基本の順位点は「重要度×2＋関心度＋新鮮さ－古さ」。その後、話題の偏りを抑えます。古い重要記事が永久に上位になる方式ではありません。DeNA以外の重大ニュースが上位になる場合があります。他に記事がなければ高校野球だけでも掲載し、件数の水増しはしません。

記事にはimportance、importance_reasons、ranking_score、ranking_reasons、display_orderを追加します。ブラウザはdisplay_orderを使い、「すべて」と個別タブで同じ並びにします。旧JSONに順位情報がなければ従来の公開日時順に戻ります。

## 同じ話題の整理
- 従来の同一URL・ほぼ同じタイトルの重複整理を維持。
- 新作名と発表の種別、DLsite/FANZAと決済・規約変更の種別、対戦カード・大会・段階・試合日を組み合わせます。
- 見出しの二文字単位の類似性も補助に使います。本文の意味を完全に理解するAIではありません。
- 別試合、別日、別作品、対応機種等の違い、独自取材・重要な続報は残す方向で判定します。
- 整理された元記事のリンクは代表記事のrelated_articlesに保持し、診断にはsame_storyとgrouped_intoを残します。画面に新しい関連記事欄は追加していません。

## 保持と取得失敗
v0.3の期間を維持します。ゲーム・野球は公開日から2日、成人向け同人の新規検索は14日。成人向け同人で従来の採用スコアが7以上の重要記事は、公開日から最大30日保持します。「注目」の新しい重要度判定とは別の保持基準です。

公開日時・初回確認日時を維持し、再取得日を公開日にしません。一部の検索失敗時は、期間内かつ採用条件を満たす前回記事を保持。全検索失敗時はnews.jsonを完全にそのまま残し、diagnostics.jsonだけを更新して終了コード1にします。全失敗の場合は期限切れ記事も残ります。

失敗・一部失敗は画面に表示します。「新着なし」とは区別します。診断のない旧JSONの空状態は「収集状況は未確認」です。JSONは一時ファイルから置換し、途中で切れたファイルにしません。

## 収集診断
ActionsのCollect newsログとdiagnostics.jsonで確認できます。

| 項目 | 意味 |
| --- | --- |
| fetched | 検索から受け取ったitemの数。検索間の重複を含む |
| accepted / excluded | 今回の採用数・除外数。fetched = accepted + excluded |
| retained / displayed | 前回から保持した件数・表示対象の合計 |
| exclusion_reasons / reason_labels | 除外理由別の件数・日本語説明 |
| queries / decisions | 検索ごとの成否、件数、記事ごとの採否・採点理由 |
| last_success_at | 1本以上のRSSを正常解析できた最終日時。0件でも成功 |
| last_complete_success_at | カテゴリの全検索が成功した最終日時 |
| top5 | 表示する上位5件と重要度・順位の理由 |
| scoring | 実行時点の採点・順位設定 |

成人向け同人のempty_reason：
- A_no_results：全検索成功・取得0件。
- B_fetch_failed：全検索失敗。
- C_all_filtered：全検索成功・取得あり・今回採用0件。
- partial_fetch_failure：一部失敗。A/Cと断定しません。
- has_articles：全検索成功・今回採用あり。

これらは今回の新規採用の状態で、保持中の記事が残っている場合があります。日時はUTCで保存します。診断は通常画面に常時表示しませんが、Pages上のJSONは公開されます。

## 公式確認
規約・審査・決済は公式ドメインを対象にした検索も実行します。RSSの媒体URLがdlsite.com/dmm.co.jp配下ならofficial_publisher_unverified、それ以外はneeds_official_reviewと記録します。どちらも変更の内容を確認済みという意味ではありません。診断のsource_urlと記事リンクから公式原文を確認してください。

## 自動更新と互換性
GitHub Actions、既存のPages設定、収集クエリと自動実行時刻はv0.3から変更していません。新しいテストも既存のunittest discoverで実行されます。手動でUpdate newsを1回実行すると、新しい順位情報がnews.jsonに付きます。

news.jsonの従来のupdated_at、articles、errors、記事の既存項目は維持しています。今回の配布物にnews.jsonを含めません。GitHub上の現行データは保持してください。

## 残る制限
- GoogleニュースRSSの登録媒体・結果上限・配信遅延に依存します。公式情報の完全な網羅や真偽確認はできません。
- 見出し・媒体に基づくルール方式で、未知の作品・選手名、否定表現、本文だけにある情報を誤判定する場合があります。
- 対戦カードや試合日が見出しから取れない場合は、同じ試合の記事が残ります。日付のない翌日のレポートは別試合との混同を避けるため、まとめられない場合があります。
- 追加情報がある記事でも、手がかりがなければ代表記事にまとめる可能性があります。元リンクはrelated_articlesに残します。
- 実運用の上位5件と診断を見て調整してください。テスト用サンプルの結果は実ニュース全体の精度保証ではありません。

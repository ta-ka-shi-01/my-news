# My News v0.3

Googleニュース検索RSSから、ゲーム業界・成人向け同人ゲーム・野球の記事を集める個人向けニュース一覧です。収集はPython標準ライブラリのみ、選別は説明可能なルール方式で、有料APIは使いません。

## 使い方
1. `python collect.py` で収集（インターネット接続が必要）。
2. `python -m http.server 8000` を実行し、ブラウザで `http://localhost:8000` を開く。
3. `python -m unittest discover -s tests` で収集テスト。
4. `node tests/test_ui.cjs` で表示処理テスト（Node.js、追加パッケージ不要）。

## v0.2からの変更
- ゲーム5本・成人向け同人8本・野球6本の検索を独立して実行。野球はDeNA以外のNPB、MLB、高校野球も検索します。
- タイトルと媒体から関連性を確認し、重要度を加点、攻略・販促・ゴシップなどを減点。決算・規約・球界の重要事項は減点だけで落とさない保護ルールがあります。
- 新しい公開日時を基本に、同じ日時ならスコアを優先。件数を埋める処理はありません。DeNA以外の件数も診断に記録しますが固定枠は設けません。
- 同一URL、媒体名を除いた同一タイトル、非常に近い長いタイトルを重複整理。数字や「延期／発売」などの違いがある近似タイトルは残します。
- タイトル末尾に一致する媒体名だけを削除。タイトル途中のハイフンは残します。
- 「すべて」の3セクション、各最新5件、もっと見る、個別タブ、カテゴリラベルを維持。
- 収集失敗・一部失敗時はその旨を表示し、「新着なし」と区別。診断のない旧データの空状態は「収集状況は未確認」と表示します。

## スコア調整
`scoring.json` で各カテゴリの以下を変更できます。

| 項目 | 意味 |
| --- | --- |
| context | 関連性を確認する語。専門媒体や公式媒体の判定はcollect.py側にもあります |
| rules | 加点・減点する語と点数。同じルールは1記事につき1回だけ加算 |
| threshold | 採用の最低点：ゲーム4、成人向け同人5、野球4 |
| important | 注目記事の最低点：各7 |
| protected_rules | 重要事項の保護。該当時はimportant以上に補正し、補正理由も記録 |
| days | 新規収集の期間：ゲーム・野球2日、成人向け同人14日 |
| retain_days | 成人向け同人の重要記事を保持する最長期間：公開日から30日 |

専門媒体は関連性の補助で、採用の保証ではありません。一般向けインディーはゲーム業界で検索し、成人向け同人では成人向け・プラットフォーム・公式媒体との接点がないものを除外します。タイトルに手がかりがなければ見落とす可能性があります。

## 保持と失敗時の扱い
- 成人向け同人の重要記事は、次回RSSに現れなくても公開日から最大30日保持します。
- 元の公開日時と初回確認日時を引き継ぎ、再取得日を公開日にはしません。再掲載で公開日時が新しくなっても、前回と同じ記事なら古い公開日時を使います。
- 一部の検索が失敗したカテゴリは、期間内で採用条件に合う前回記事も保持します。重要成人向け同人は30日、その他は各カテゴリの通常期間が上限です。
- 全検索が失敗した場合はnews.jsonをバイト単位でそのまま保存し、diagnostics.jsonのみ更新。終了コード1でActionsの失敗として通知されます。この場合は期限切れを含む旧記事も残ります。
- JSONは一時ファイルから置換し、書きかけのnews.jsonを公開しません。

## 診断の読み方
`diagnostics.json`とActionsの「Collect news」ログで確認できます。診断は画面に常時表示しませんが、GitHub PagesではJSON自体は公開されます。

| 項目 | 意味 |
| --- | --- |
| fetched | 検索で受け取ったitem数。検索をまたぐ重複も含む |
| accepted / excluded | 今回採用・除外した数。fetched = accepted + excluded |
| retained / displayed | 前回から保持した数／表示対象の合計 |
| exclusion_reasons | 理由別の除外数。reason_labelsに日本語説明 |
| queries | 検索文、成功・失敗、件数、エラー |
| decisions | 記事ごとのスコア・加減点理由・採否・検索文 |
| last_success_at | 1本以上のRSSを正常に解析できた最終日時。記事0件でも成功 |
| last_complete_success_at | そのカテゴリの全検索が成功した最終日時 |
| scoring | 実行時点の採点設定の控え |

`empty_reason`は新規採用に関する状態です。保持中の記事がある場合もあります。
- `A_no_results`：全検索成功、取得0件。
- `B_fetch_failed`：全検索失敗。
- `C_all_filtered`：全検索成功、取得あり、採用0件。
- `partial_fetch_failure`：一部失敗。A/Cと断定しません。
- `has_articles`：全検索成功、今回の採用あり。

最終成功日時はUTC（末尾+00:00）で保存し、記事画面は閲覧端末の日時設定で表示します。

## 公式確認
成人向けの規約・審査・決済は公式ドメインを対象にした検索も実行します。
- `official_publisher_unverified`：RSSの媒体URLがdlsite.com/dmm.co.jp配下。公式発信候補ですが、本文は未確認。
- `needs_official_review`：公式の原文確認が必要。

公式検索が成功しても変更内容の真偽を自動確認したことにはなりません。diagnostics.jsonのsource_urlと記事リンクから原文を確認してください。公式ページがGoogleニュースに登録されていなければ取得できません。

## 自動更新・GitHub Pages
既存の6時間ごとの実行（UTC 0:13 / 6:13 / 12:13 / 18:13）と手動実行を維持します。テスト後に収集し、news.jsonとdiagnostics.jsonをコミット。全取得失敗でも診断をコミットし、診断ファイルをActionsのArtifactsに14日保存します。GitHub Actionsでcontents:writeを許可してください。Pagesの既存設定は変更不要です。公開反映と実際のActions実行は反映後に確認してください。

## 制限
- RSSの登録媒体・検索結果上限・検索構文の解釈・配信遅延に依存します。公式情報や重要記事を網羅できません。
- 本文を読まず見出し・媒体に基づくため、誤採用・見落とし・過剰な重複整理が残ります。ルールは実運用の記事を見て調整してください。
- RSSの日時を完全には検証できません。再配信された古い記事は、履歴に同じ記事がないと判別できない場合があります。
- 類似記事整理は保守的です。同じニュースでも見出しが大きく違えば両方残ります。
- Googleニュースの中継リンクを使用し、本文は転載しません。
